# 决策规则速查 — AI Agent 手册（AI Agent HandBook）

| 能力 | 一句话规则 |
|---|---|
| 形态与成熟度选型（四维形态判断 · L1-L4 · 最低充分架构） | 形态看四维、成熟度看治理，升级须双条件，永远选最低充分架构。 |
| Harness 构建入口选择（契约先行 · 四判据四入口 · 责任矩阵） | 先定任务契约，再用四判据选构建入口；托管转移执行，不转移业务正确性。 |
| 任务契约（Agent Loop 状态机 · 预算边界 · 委派七要素 · 五级完成验证） | 模型只能申请完成，Harness 凭环境证据提交完成；每个等待都要显式成状态、每种消耗都要进预算。 |
| 信息契约（Context 编译管线 · 压缩保留八类 · Manifest 审计） | Context 是编译产物不是历史堆积：权限过滤先于排序，关键事实先落权威状态再移出窗口，压缩按八类保留并用五指标验收。 |
| 状态分层（Call/Session/Task 三分 · 三表示 · Memory 写入六问 · 信息五分法） | 五类信息各有去向：Context 看见、State 恢复、Workspace 工作、Memory 积累、Knowledge 权威——分库分治，写入先过六问。 |
| Skill 资产化与渐进披露（沉淀四步 · 三层披露 · 发布链反退化） | 一次成功不是能力：Skill 须清洗、测试、版本化、走发布链，经渐进披露进窗口，且永不自带权限。 |
| 行动契约（行动链七步 · 看见/注册/授权三分 · ALLOW/DENY/ASK · PACV + HITL） | 看见≠注册≠授权：行动走七步链，权限按要素决策（非工具名白名单），不可逆动作走 Preview-Approve-Commit-Verify。 |
| 沙箱与 Agent Runtime（环境契约+隔离分级+等待分档+接管围栏） | 先按负载交付环境契约（模板/挂载/保留/验收/释放），再按代码可信度与租户边界选隔离后端和入口；等待期四档取舍，接管靠执行代次围栏拒绝旧实例写入。 |
| Agent 状态存储分层选型（四类状态×正确性边界×物理承载） | 先定义每类状态对象的正确性边界，再匹配物理承载——权威事实强一致、派生视图知新鲜度；选型按五问验收（原子提交/引用稳定/撤回及时/独立恢复/完整导出），不按产品名称。 |
| AI 网关三语义治理（准入四步+预算不变量+重试预算+任务账本） | 网关只做准入、转发与记录：错误分类先于重试且预算跨层原子扣减、严格预算预留不变量、MCP 准入四步+权限取交集、审批状态化批准后重准入；完成与否由执行系统判定。 |
| 异步任务与完成语义分层（六对象权威+五层完成+九状态机） | 进程结束只是执行状态：六对象分权威、完成语义五层到 Outcome（Evidence+Verifier 判定）、恢复与幂等责任在执行端；带环流转用状态机，不把环塞进 DAG。 |
| 多 Agent 团队与编排（收益成本判据+三拓扑+三层聚合+权限交集） | 先过收益成本判据再组队；拓扑按决策/委派/汇报关系三选（非演进阶梯），根 Task 前定团队级停止条件，提交/接受/根完成三层判定不可互相替代，权限取五方交集。 |
| Agent 分布式通信选型（四面×四档+契约六要素+续传点） | 先重检四假设（耗时有界/会话-连接/等待资源/端点变化），再按通信面×交互语义档逐段定位，用契约六要素量尺查协议缺口；流结束≠任务结束，状态承载三位置决定恢复方式。 |
| 可观测性与审计（观测矩阵 + Span 层级 + 指标下钻 + 证据链闭环） | 先用"四维度×三层对象"矩阵规划看什么看哪里，再用统一 Span 层级与执行语义建可聚合的 Trace，排障走"指标→下钻"，审计以四要素证据链和分层研判闭环交付。 |
| Agent 安全防护（盾与缰绳 + 五攻击面 + 双向授权 + 出站默认拒绝） | 以"盾（全栈纵深防打穿）+ 缰绳（身份/逐次校验/二次授权/出域阻断防越界）"双主线，按五类攻击面做威胁建模，身份走八环节闭环与 Token Exchange 权限收敛，计算层会话级隔离、网络出站默认拒绝。 |
| AI 资产注册、版本与发现（结构化引用 + 不可变版本 + 发布 Pipeline + L0-L5 演进） | 把 Prompt/Skill/MCP/Agent/AgentSpec 统一为"逻辑资源+不可变版本+结构化引用+Resolver 解析"，经有序发布 Pipeline 与评测版本绑定发布，发现与治理资格分离，按 L0-L5 以实际能力为准演进。 |
| 上线前 Agent Simulation（约束不可靠内核 + Scenario Spec + Manifest/Run Result + 证据分层） | 在满足"不触达未授权生产、不产生不可控副作用"的受控环境里，用 Scenario Spec + 不可变 Manifest + Run Result 证据链验证 Agent 行为：SUT 是内容不可替换、其余是条件必须替换，四维状态独立记录，零违规结论按 3/n 置信上界表述。 |
| 调优归因与模型调优路线（归因次序 + 三层验证 + 四组对照 + SFT/RL/蒸馏 + 五门禁灰度） | 效果问题先固定两层验证一层（绕过模型直调工具查环境→固定模型环境修上下文协议查 Harness→跨任务稳定复现才归模型），归因模型后才按"可示范→SFT / 可验证反馈→RL / 教师领先→蒸馏"选路线，验收走自主运行四维报告与五门禁灰度。 |
| 轨迹数据与运行时 Pipeline（Trace/Session/Trajectory + 相邻事实链 + 行粒度先行 + 周期质检） | 轨迹按问题选入口（TraceID/SessionID/条件筛选/语义搜索）、先读输入输出再核关键工具动作、结论写成相邻事实链 A→B→C；Pipeline 先定"一行代表什么"，预览验证普通任务可读且异常任务保留，再周期任务化输出固定质检数据集。 |
| 黄金数据集与 Badcase 闭环（建集四步 + 五类覆盖 + 评估器试评 + 四类分流 + 单变量实验 + 三检查采用） | 黄金集 = 业务确认的题目 + 可判定完成依据（建集四步 + 五类覆盖），评估器先对已知好/坏/信息不完整样本试评，Badcase 按四类现象分流后单变量实验（被评的必须是本次新生成回答），采用前过三检查（严重错误消失/正常不退化/耗时可接受）再扩回归集。 |
| 受控自进化（五路改进方向 + 经验库核验 + 召回实验 + 四类资产化 + 三档成熟度四确认） | 按现象选五路（经验库/Skill/SQL 模板/Workflow/Harness），经验须回 Trace 核验"解决什么/建议什么/何时适用"，召回靠 Baseline 对照实验调五因素，Badcase 改成逐项对应执行证据的局部修改并经三组任务验证，采用前四确认且始终保留恢复原配置办法。 |
| 边缘与全球优化（就地三条件 + 四维指标准入 + 语义缓存边界 + 区域对比归因 + 三阶段/成熟度） | 边缘只接"无权威状态判定 + 无写副作用 + 符合驻留"的请求，缓存键含租户/权限/版本六维防串租户，多区域失败查 Skill、单区域失败查路由，全球 P95 不达标阻断发布，阶段按信号表选且"不优化"也是正确选择。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
