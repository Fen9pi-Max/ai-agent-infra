# 黄金数据集与 Badcase 闭环（建集四步 + 五类覆盖 + 评估器试评 + 四类分流 + 单变量实验 + 三检查采用）

## R（原文摘引）
> 黄金数据集是一组经过业务确认的任务：既有题目，也有判断任务是否完成的依据。……Agent 曾经答错的任务，只要补齐了正确要求，同样可以成为黄金样本。（21.1）
> 证据暂缺或还在争论的样本继续留在候选集，补齐后再收入。已经确认有问题的样本称为 Badcase；把它的正确要求补好，才能用于检验下一次修改。（21.3）
> 只收集低分题，可能看不到正常能力的退化；只收集最常见问题，又容易漏掉代价很高的少数情况。（21.4）
> 参与改写 Prompt、生成 Skill 或提炼经验的题，与最后独立检查效果的题分开。将未参与优化的那部分留作独立验证。一旦反复查看这些题并据此修改 Agent，它们就已参与调优，应另留新的验证题。（21.6）
> 至少覆盖一条已知好回答、一条已知坏回答，以及一条信息不完整的样本。检查时可以直接问：扣分依据是否真的出现在这条回答中？（22.2）
> 总分告诉团队先看哪里；解释帮助判断问题是否成立；轨迹则用于确认为什么出现这个问题。不要看到低分便立即改 Prompt。（22.3）
> 决定采用候选时，除了平均分，至少再看三件事：严重错误是否消失，原来正常的场景是否退化，耗时与消耗是否可接受。（22.6）

## I（解释）
1. **黄金集 = 题目 + 可判定的完成依据**：知识问答给参考答案与必含要点，操作任务给业务应达到的状态；"黄金"指题目与标准可信——答错的题补齐正确要求后同样是好样本，往往比只收集漂亮成功回答更有助改进。价值来自反复使用（定标准/选型/验证修改/防回归/校准评估器五种用途），从未进入评估的数据集不参与改进。
2. **建集四步**：候选集集中收集（来源列区分真实与专家编写）→ 用少量起步字段说清题目和标准（input/actual_output/expected_output/rubric/scenario/source_ref；rubric 写成可判分条款，开放任务不要求逐字一致）→ 先手工确认典型题暴露标准分歧，再 AI 预标注批量扩大 → 复核选入黄金集并核对字段映射。证据暂缺或仍在争论的留在候选集，不硬收。
3. **覆盖五类防两类盲区**：高频问题、已发生过的问题、业务边界与高风险、原本表现正常的题（检测退化）、表述变化与多轮题（防只适配一种问法）；优先补空缺比增加近似问题有价值。
4. **评估器先试评再扩大**：按需三选（确定性检查 Code / 切题性与遗漏 LLM / 多步完成度与轨迹一致性 Agent，可组合）；用已知好/坏/信息不完整样本验证——扣分依据是否真出现在回答中、是否引用正确工具结果、缺证据时是否说明无法判断。坏回答得高分先查字段映射再查评分条款。
5. **Badcase 四类分流，先确认再动手**：原始问题、回答、分项判断、解释、轨迹放一起读——回答确缺内容→纳入调优样本；评分与轨迹矛盾→修评估器或映射并重评；Agent 声称完成但工具失败→交执行团队；材料缺失→先补执行条件。低分不等于 Badcase，"看到低分立即改 Prompt"是被点名禁止的动作。
6. **实验单变量 + 采用三检查**：固定 Baseline，第一轮只改最有依据的一项；被评分的必须是本次新生成的回答与轨迹（评旧回答=实验空转）；先跑两题确认逐题 rubric 生效；采用前看三件事（严重错误消失/正常场景不退化/耗时消耗可接受），总分提高但关键条款未过不适合升级；通过后扩大到回归集与独立样本。版本纪律：比较前建版本冻结，调优题与独立验证题分离防泄漏。

## A1（原书案例 + 合成演练）
- 原书调研（2026 报告·七）：评估普遍停留在人工抽查（55%），轨迹自动评估仅 6%，28% 无系统性体系——而有评估手段的企业任务成功率达 70% 以上者约为无评估企业的两倍（c-06/c-07），直接支撑"评估基线是持续改进抓手"。实践篇：Mamba Insight 把 500+ 条历史数据需求逐条标注，暗知识固化为 9 个结构化 Skill 文档 + 45 组 QA 对资产，口径错了回流语义层修正、意图偏了回流为新的已验证问答（c-37，目标提效 10X、达成比例未说明）。
- 合成演练（原书未提供该场景完整记录，按 21.3/22.1-22.6 规则推演）：IT 工单 Agent 漏分 VIP 工单。建候选集（漏分轨迹 + 正常样本，来源列区分）→ 起步字段六件套，rubric 写成可判分条款（如"VIP 判定正确 0.4 分"）→ 先手工确认典型题再 AI 预标注 → 复核选入 it_dispatch_gold_v1 并核对字段映射。评估器先对已知好/坏/信息不完整三条试评，检查扣分依据；评分与轨迹矛盾先查映射再定性。实验只改工单分类 Prompt 单变量，五变量映射后先跑两题验证逐题 rubric 生效；采用三检查通过后扩大到回归集。

## A2（情境应用）
场景：团队对"什么算回答好"没有共同标准时；要选模型或 Agent 方案但不想只信通用榜单时；一次修改（Prompt/模型/Skill）上线前要验证有效性时；评估器打分不被信任时；版本升级前做回归检查时。
语言信号：「怎么判断回答好不好」「建个评测集 / 题库」「评估器准不准」「这次改动到底有没有效」「升级前跑哪些题」「低分样本怎么处理」「golden set / rubric / badcase / 评估器 / A-B 实验 / 回归」。
区分（初稿）：trajectory-pipeline 负责把运行记录变成候选样本，本卡从"业务确认"接手；确认 Badcase 后的 Skill/Harness/经验资产改造归 controlled-evolution；要不要训模型、训练类改动的门禁与灰度归 tuning-attribution，本卡的实验基础设施同时服务它。

## E（执行步骤）
输入契约：一个具体业务问题（如"答了概念却没解决问题"）+ 好/坏回答样本若干 + 候选样本来源（trajectory-pipeline 产出或人工收集）+ 业务确认人；无业务确认人时停在候选集阶段，不自行拍板标准。
1. 建候选集并定起步字段：六件套字段（input/actual_output/expected_output/rubric/scenario/source_ref）；参考答案给合格示例，rubric 写成可判分条款（分值/通过条件，如"编造能力标记不通过"）。完成标准：字段齐全 + 来源列区分真实与专家编写。
2. 确认与选入：先手工确认几条典型题（提前暴露标准分歧）→ AI 预标注批量分类/预筛 → 多人复核，参考答案与 rubric 填到约定字段 → 筛选加入黄金集（如 xxx_gold_v1）并核对字段映射；证据暂缺或有争论的留候选集。完成标准：黄金集 v1 + 逐题 rubric + 复核记录。
3. 覆盖检查（五类）：高频 / 已发生 / 边界与高风险 / 原本正常 / 表述变化与多轮；操作题写明起始条件（如"订单满足退款条件"）；同类问题保留不同权限/版本/上下文的区别。完成标准：覆盖表 + 空缺清单（补空缺优先）。
4. 评估器建设与试评：按检查性质三选评估方式（可组合，需总分时明确计算方式，不简单平均）；对已知好/坏/信息不完整样本试评，逐条问"扣分依据是否真出现在回答中""是否引用正确的工具结果""缺证据时是否说明无法判断"；坏回答得高分先查字段映射再看条款，调整后重评同批。完成标准：校准样本上的一致性记录（含误判样本留档作校准材料）。
5. Badcase 筛选分流：先看整体分布再开具体样本，带任务与时间范围避免混标准比较；把原始问题、回答、分项判断、解释、轨迹放一起读，按四类分流（纳入调优样本 / 修评估器与映射并重评受影响样本 / 交执行团队 / 先补执行条件）；同种遗漏选代表几条 + 边界场景 + 部分正常任务；高分样本适当抽检。完成标准：确认的 Badcase 清单 + 评估器修正项 + 实验候选题。
6. 配实验：先记录 Baseline；第一轮只改最有依据的一项；五变量映射——用户输入/Agent 输出/运行轨迹均取本次新生成，参考答案与 rubric 来自数据集；先跑两题打开解释确认逐题 rubric 生效（评到旧回答须先修映射重跑）；需要工具状态时接 Pipeline 加工实验轨迹；正式比较用为本轮冻结的独立黄金集，评分标准、版本、Prompt 与关键参数同步记录。完成标准：逐题对比记录 + 配置留档。
7. 采用决策与回归：按"退化题→改善题→关键正常场景"顺序读差异；区分评估器波动（对固定回答重复评分）与 Agent 波动（重跑同批题）；采用三检查 + 关键条款硬门槛（总分升但关键条款未过不升级；输出变长、省步骤的低耗时都不是升级理由）；通过后扩大到历史回归集与未参与本轮修改的独立样本。完成标准：采用/不采用决策 + 可追溯的对比证据；重要题纳入升级前回归。
输出契约：黄金集版本（含逐题 rubric）、评估器配置与校准记录、确认 Badcase 清单、实验对比记录与采用决策。
判停：参与优化（改 Prompt/生成 Skill/提炼经验）的题与独立验证题必须分离——反复查看并据此修改 Agent 的题已参与调优，须另留新验证题；比较期间不追加不修改本题集。

## B（边界）
- 看到低分立即改 Prompt：低分可能是评估器误判、执行异常或材料缺失——不经解释与轨迹确认就动手，把非模型问题当模型问题修；同理，分数起伏不能一律归因 Rubric。
- 评估器自身三类失效：字段误接（最终回答接到工具输出，不报错只产生系统性偏移分数）、无证据打分（输入只有文件链接或"已完成"也输出确定分数）、关键词匹配（提到某词≠用户能完成下一步）；只评礼貌不查业务结果会让执行类失败结构性不可见；多评估器简单平均会稀释关键维度。
- 覆盖与抽样偏差：只收集低分题看不到正常能力退化，只收集最常见问题漏掉高代价少数情况；实验集全红（全是失败样本）无法检测退化；从不抽检高分样本则评估器漏判的严重问题留在盲区；误判样本直接丢弃等于放弃免费的评估器回归集。
- 泄漏三通道：同一任务的近似改写同时进训练集与测试集；长期用同一留出集选版本产生间接过拟合；调优题与验证题不分——反复看过并据此改过 Agent 的题已参与调优。
- 比较公允性：不同标准/业务的数据混比；结果出来后临时更改统计方式；仅沿用同一服务地址就认为配置相同；成本比较不固定任务构成（放弃困难任务制造表面降本）。
- 采用纪律：总分提高但关键条款未通过不升级；输出变长、省略必要步骤的低耗时不是升级理由；API 受理成功≠题目完成（异步须等最终回答）；相互独立样本用独立会话防上下文串扰。
- 与相邻能力分工：轨迹检索、留样与 Pipeline 归 trajectory-pipeline；确认后的 Skill/Harness/经验资产改造与经验库归 controlled-evolution；训练路线选择、五门禁与模型灰度归 tuning-attribution；百炼 Dataset/评估任务/本地实验 SDK 等产品操作为 reference，字段映射、rubric 写法、单变量纪律与三检查为通用方法。
