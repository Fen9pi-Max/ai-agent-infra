# 信息契约（Context 编译观 + 八步管线 + 压缩保留八类 + Manifest 审计）

## R（原文摘引）
> Context Engineering 的本质不是把所有内容塞进更长的窗口，而是在正确的时间选择正确的信息。（第 2 章 2.2.3）
> 其角色更接近一次"编译"：多个来源按优先级合并，冲突被处理，超出预算的内容被压缩或移除，最终得到本轮可执行的模型视图。（第 5 章 5.1）
> 管线应先做身份和权限过滤，再做相关性排序，不能为了排序方便先把跨租户内容交给检索器或模型。（第 5 章 5.1）
> 任何会影响后续行动的事实，都应先进入权威状态，再允许从活动上下文中移出。（第 5 章 5.2）
> 压缩质量不能只看节省多少 Token。（第 5 章 5.2）

## I（解释）
1. **编译观**：System Prompt 不是仓库里的长字符串，而是按 Agent 版本/任务阶段/用户身份/工作区规则/预算/工具/Skill 每轮动态编译。System Context 六层（平台政策→Agent 契约→租户规则→运行时提醒→选中 Skill→工具描述），Task Context 七层（目标/Steering→Plan/Todo→最近交互→压缩历史→检索事实→工作区引用），四条越级覆盖禁令（项目文档不能覆盖平台政策、用户最新要求不能突破安全边界、Memory 不能替代当前事实、工具返回不能升为系统指令）。
2. **八步确定性管线（顺序不可换）**：读 Task State→解析身份与作用域→收集候选→权限与可信度过滤→相关性排序去重→Token 预算分配→压缩引用化→按层编译→生成 Manifest。权限过滤先于排序是红线：跨租户内容一旦进了检索器就已是隔离失败。
3. **优先级七因子与预算分区**：约束强度/任务相关性/时间有效性/来源可信度/执行依赖/信息增量/Token 成本综合排序，不能只按相似度。窗口分固定下限区（不可覆盖规则+当前目标）、动态区（最近交互/检索/Skill/工具 Schema）、输出预留区，随任务阶段动态调整。
4. **"最近"按任务语义而非时间**：未解决错误、待审批动作、验收失败证据、用户对目标的最新修改，即使产生更早也是活动状态；已由 Artifact 证明的探索过程可退出窗口。压缩保留八类（目标约束/已确认事实/决定与被否决方案/行动副作用/Plan 阻塞/Artifact 引用/审批权限/失败尝试），生命周期 Commit→Compact→Rebuild→Validate；高风险事实从 Task State 确定性提取，模型只压缩叙述性内容。
5. **卸载、Reset 与审计**：数万行大结果写 Workspace/Artifact Store，窗口只留摘要+片段+稳定引用+读取时版本；多次压缩仍不足时 Reset，从 Continuation Package 八项重建。每次调用生成 Context Manifest（来源/作用域/版本/信任级/选择理由/变换/hash/省略原因）——模型为何遗漏、两版本差异、敏感内容来源三问皆可审计；压缩质量看五指标（事实保留率/继续成功率/矛盾率/引用可用率/成本收益）。

## A1（原书案例 + 合成演练）
- 原书·调研数据（2026 调研报告）：上下文与记忆管理是 90% 企业的明确需求（c-04）；上下文问题前两位是检索不准（54%）与记忆更新/遗忘机制缺失（48%），窗口限制只排第三——不是靠扩大窗口能解决的问题（c-10）。
- 原书·实践案例：MiniMax 以 PolarDB 承载海量长周期记忆，千亿级对话表读写性能提升超 3 倍、存储成本降 75%——长会话信息底座的工程量级参照（c-34）。
- 合成演练（纸面推演，非原书案例）：客服会话已 40 轮，订单接口刚返回 200KB 明细，用户 3 轮前升级投诉未解决。管线按序执行：身份作用域过滤→收集→权限过滤→排序去重→预算分配→压缩引用化→编译→Manifest；订单原文卸载 Workspace，窗口留摘要+首尾片段+稳定引用+读取时版本；"最近"判定——3 轮前的未解决升级投诉属活动状态，已由 Artifact 证明的探索过程退出窗口；压缩八类逐项勾选，退款审批等高风险事实从 Task State 确定性提取不走模型摘要；预算分区（规则+当前目标=固定下限，交互/检索=动态，输出=预留）。核验：Manifest 字段齐备可回放，Validate 步用续行用例验证无漂移。

## A2（情境应用）
场景：长会话/长任务上下文膨胀、压缩后丢关键信息时；设计每轮给模型看什么的装配管线时；多租户/多来源内容要进窗口时；要解释"模型为什么没看见/为什么泄漏"时。
语言信号：「上下文爆了怎么办」「压缩把关键事实压没了」「长对话越聊越笨」「System Prompt 怎么组织」「context window / compaction / 上下文管理 / 记忆检索进窗口」。
区分：state-layering 管压缩/卸载/Reset 产出的落点（存哪、如何分层治理），本卡只管窗口内视图与装配管线；skill-asset 管 Skill 资产侧治理，本卡只管"选中 Skill"这一层如何进窗口；task-contract 定义任务状态语义（本管线消费它，不定义它）。

## E（执行步骤）
输入契约：Task State（目标/阶段/预算）、调用身份与作用域（租户/项目/用户/任务）、候选信息源清单（规则/历史/Workspace/Memory/Knowledge/Skill/工具 Registry）、窗口总额与分区约束。
1. 定分层与禁令：列出 System Context 六层/Task Context 七层的实际条目与来源，标注四条越级覆盖禁令的执行点。完成标准：每层有来源与责任方，禁令有机制承载（非提示词）。
2. 跑八步管线（顺序固定）：权限过滤在排序之前；外部内容保留来源与信任等级。完成标准：逐步骤可核对，无"先检索后过滤"倒置。
3. 预算分区与七因子排序：固定下限区/动态区/输出预留区划界；候选按七因子排序去重。完成标准：分区数值表 + 排序因子说明（权重按任务设定并记录为约定）。
4. 卸载与压缩：大结果（数千行级）写外部存稳定引用；压缩按八类保留清单勾选，高风险事实确定性提取；执行 Commit→Compact→Rebuild→Validate。完成标准：八类逐项在/不在+理由；Validate 有续行用例。
5. 出 Manifest 并验收：记录十字段（source_type/source_id/scope/version/trust_level/permission_basis/selected_reason/token_count/transform/content_hash + omitted 及原因）；用五指标评估压缩质量。完成标准：单次调用可回放重建；五指标有度量值而非"省了 X Token"单一数字。
输出契约：编译后的模型输入 + Context Manifest + 压缩质量五指标记录。判停：无权威状态存储（Task State 不存在）时先回 state-layering 建状态层——没有它，"先落状态再移出"不可执行，压缩必然改变任务事实。

## B（边界）
- 简单截断最早历史会丢初始目标与关键决定（ce-17）：关键约束往往早期建立而全程有效，"越旧越不重要"与任务结构相反。
- 影响后续行动的事实未先落权威状态就移出窗口（ce-18 / ce-05）：审批结果、工具提交、用户变更被模型自由归纳，一次不准确摘要就永久改变任务真实状态，任务失去可恢复性。
- 卸载引用不稳定或无版本标识（ce-19）：临时 URL 恢复时失效；时变内容不记读取版本，新内容与旧推理混读。
- 压缩质量只看省 Token（ce-20）：事实丢失、摘要与权威状态矛盾、引用失效不可见，错误压缩在续行失败时才暴露且难归因。
- 大结果反复进每轮窗口（ce-21）：成本与延迟随轮次线性放大，注意力退化导致偏离目标——卸载省的是后续每一轮。
- 原书明示边界：七因子权重与压缩阈值无通用量化值，须按任务设定并版本化（压缩器、摘要 Schema 进回归范围）；Context Policy 与可运行 Agent 版本绑定。
- 适用边界（原书视角）：分层结构（六层 System/七层 Task）出自企业多租户白皮书语境，个人/单租户项目可裁剪层级，但"权限过滤先于排序""先落状态再移出"两条红线不因规模小而豁免。
