# 边缘与全球优化（就地三条件 + 四维指标准入 + 语义缓存边界 + 区域对比归因 + 三阶段/成熟度 + 六类不适用）

## R（原文摘引）
> 分工原则是：边缘能处理的（缓存命中、安全拦截、就近路由），就不回源 Region；边缘处理不了的（复杂推理、状态变更、长任务执行），才进入 Region。（24.1）
> Agent Release 的准入基线应同时包含 Region 内指标和边缘指标——一个版本如果在全球 P95 延迟上未达标，即使 Region 内评估全部通过，也不应被发布。（24.2）
> 语义缓存应限定在公开、幂等、低风险请求范围内，并把租户、权限域、地区、模型、Prompt 和知识版本纳入缓存键，定义 TTL、失效、来源标记和回源策略，避免跨租户泄露、越权、版本陈旧和个性化答案误命中。（24.3）
> 例如，某个工具在多个区域都失败，问题可能出在 Skill 本身；如果只在一个区域失败，更可能是网络或服务路由问题。（24.4）
> 三个阶段的关系与"选择最低充分架构"原则一致——边缘优化同样不追求最高阶段，而是根据业务的全球化程度选择成本与收益最优的阶段。（24.8）
> 流量规模小或缓存命中率低时，边缘层的额外成本可能超过收益，此时阶段一甚至"不优化"才是正确选择。（24.9）

## I（解释）
1. **分工按维度划界，不按算力**：正确性、复杂推理、状态变更归 Region；网络传输、全球就近接入、缓存命中、到达 Region 前的威胁拦截归边缘。判断"边缘能处理"看三个条件——无需权威状态判定、无写副作用、符合数据驻留；涉及一致性、顺序与恢复语义的操作必须回 Region。端到端延迟七因素中六个在 Region 内，仅网络传输由物理距离决定，所以边缘优化精准命中的就是这一项。
2. **全球指标进发布门禁**：边缘评估四维——性能（分区域 TTFT P50/P95/P99、传输延迟）、成本（端到端调用成本、语义缓存节省、回源占比）、安全（边缘拦截率、Injection 检出）、体验（区域一致性、流式完整性、断连恢复）；经数据管道与 Region 内评估合并成"全球交付质量报告"，全球 P95 不达标即阻断发布。
3. **语义缓存有安全边界**：只限公开、幂等、低风险请求；缓存键必须含租户、权限域、地区、模型、Prompt 与知识版本，并定义 TTL、失效、来源标记与回源策略——否则跨租户泄露、越权、版本陈旧、个性化误命中。高正确性风险内容（个性化强、权限敏感、时效高）不进语义缓存。
4. **数据驱动归因用区域对比**：合并边缘观测与 Region 日志后，多区域失败→Skill 本身；单区域失败→网络/路由。"看到失败就改 Prompt"在这里同样是错误归因；配置采用"全球统一基线 + 区域自适应"（Prompt/核心 Skill/安全规则全球统一，路由/缓存/安全策略按区域流量调）。
5. **两种一致性区分**：治理规则全球一致（版本管理、变更评审、发布流程），数据分布按驻留差异化（分类分级、脱敏、驻留与删除按区域合规）；资产用版本钉扎 + 激活协议防"某边缘跑 v1.2 而 Region 已 v1.3"的行为漂移。
6. **安全三层 + 仿真闭环 + 阶段选择**：边缘做网络层（DDoS 吸收）、应用层（WAF/Bot）、语义层（AI 护栏拦直接注入）三层过滤，深层检测与间接注入（检索内容、工具返回）仍在 Region。仿真（上线前，"如果发生 X 会怎样"）与边缘生产验证（上线后，"真实用户实际怎样"）互补，真实参数回流仿真。演进三阶段（基础设施增强→能力下移→边缘原生部署）+ 成熟度 L1-L4，遵循"最低充分架构"：不追求最高阶段，按信号表选；单区域业务可以完全不优化。

## A1（原书案例 + 合成演练）
- 原书实践篇：吉利汽车数百业务系统、多云异构，智能运维先统一数据底座（云监控 2.0）再统一建模，从低风险测试环境切入建立信任后扩大到生产——与边缘优化"先治理与观测、按场景渐进放量、不追求一步到位"的阶段选择逻辑同构；访谈未给出落地后量化 MTTR（c-31）。
- 合成演练（原书未提供该场景记录，按 24.1/24.9 规则与示例数字推演）：跨境电商 Agent，Region 在美东，欧洲用户抱怨慢、Region 内指标正常。延迟七因素拆解：排队 50 + 环境准备 200 + 推理 1200 + 工具 800 + 网络传输 950 + 沙箱 300 + 人工 0 = 3500ms，网络传输 27% 为最大可边缘命中项；信号表（全球抱怨延迟但 Region 指标正常）→ 阶段一（基础设施增强）。逐项核对六类不适用：非单区域✓、数据驻留（GDPR→缓存按区域配置）、高正确性风险内容不进语义缓存、成本反转检查（欧洲流量占比是否够）。请求分类：商品问答（缓存命中、无权威状态、无写副作用、符合驻留）可边缘就地；订单状态变更（写副作用）必须回 Region。缓存键纳入租户/权限域/地区/模型/Prompt/知识版本。可核验输出 = 阶段决策 + 请求分类表 + 缓存键设计 + 分区域 TTFT P95 指标集。

## A2（情境应用）
场景：海外/远距离用户抱怨慢但 Region 内指标正常时；Token 成本线性上升想上语义缓存时；有数据驻留合规（GDPR 等）要求时；多区域出现同类故障要归因时；发布基线要不要纳入全球指标时；决定要不要投入边缘原生架构时。
语言信号：「海外用户慢」「边缘 / 就近接入 / edge」「语义缓存会不会串租户」「数据不能出境 / 驻留」「多区域怎么排障、怎么灰度」「TTFT / P95 / 回源比例」。
区分（初稿）：tuning-attribution 的灰度对象是模型发布单元，本卡的灰度对象是边缘站点配置（缓存/安全/路由），两者不可混用同一套放量逻辑；golden-badcase 提供评估基线思想，本卡的准入指标数据源是边缘观测而非题库；trajectory-pipeline 的轨迹加工方法可复用于边缘 Trace，但归因映射表（区域对比）是本卡特有。

## E（执行步骤）
输入契约：用户与 Region 的地理分布 + 延迟/成本结构（至少分区域 TTFT 分位数）+ 数据驻留与合规要求 + 请求类型清单（含是否有写副作用/是否需权威状态）。缺分区域观测数据时先接观测——原书全部性能数字为示例假设，阈值必须由企业基线与压测校准后才能设定。
1. 判断是否需要与所需阶段：核对信号表——全球用户抱怨延迟但 Region 指标正常→阶段一；Token 成本线性上升且无缓存手段→阶段二；每区域独立部署运维不可控→阶段三；单区域运行→暂不需要。逐项核对六类不适用场景（单区域 / 严格驻留 / 高正确性风险 / 边缘算力受限 / 区域能力差异 / 成本反转）。完成标准：阶段决策 + 信号与不适用逐项核对记录。
2. 请求分类与路由：按三条件给每类请求判定——无需权威状态判定 + 无写副作用 + 符合驻留 → 边缘就地（缓存命中、安全拦截、就近路由）；涉及状态变更、一致性顺序恢复语义、复杂推理 → 回 Region。完成标准：请求分类表（每类含判定依据）。
3. 缓存与传输优化安全边界：只对公开、幂等、低风险请求开语义缓存；缓存键纳入租户/权限域/地区/模型/Prompt/知识版本；定义 TTL、失效、来源标记、回源策略；个性化、权限敏感、时效高的内容列入排除清单。完成标准：缓存键设计 + 排除清单 + 四项成本指标（Token 节省、回源带宽、端到端成本、命中率趋势）的观测安排。
4. 指标与发布准入：按性能/成本/安全/体验四维采集边缘指标，经统一数据管道与 Region 内评估合并为全球交付质量报告；把边缘指标写入 Release 准入基线（全球 P95 不达标阻断发布）。完成标准：含边缘指标的发布基线 + 数据回流链路说明。
5. 数据驱动归因与配置治理：合并边缘观测与 Region 日志，按现象映射表定位问题层（区域慢→路由；部分区域超时→工具路由与重试；命中率区域偏低→缓存键与 TTL；回源偏高→卸载规则），用区域对比区分 Skill（多区域失败）与网络路由（单区域失败）；配置按"全球统一基线 + 区域自适应"管理。完成标准：归因结论 + 灰度验证的 Patch 记录。
6. 内容分发与版本一致性：发布触发全球同步与边缘缓存刷新；版本钉扎 + 激活协议固定各执行点版本；治理规则全球一致、数据分布按驻留差异化；边缘完成 HTML→Markdown 等内容转换。完成标准：版本策略 + 变体配置说明。
7. 仿真互补闭环与灰度：上线前仿真覆盖边界长尾（弱网、红队样本），上线后边缘观测真实分布，差距用真实参数回流仿真补场景；新缓存/安全/路由配置走站点级三环境灰度（开发/灰度/生产），按成功率/时延/命中率/拦截率决定全量或回滚。完成标准：闭环记录 + 灰度决策与回滚路径。
输出契约：阶段与成熟度决策、请求分类表、缓存键设计与排除清单、分区域 TTFT P95 指标集、含边缘指标的发布基线、灰度/回滚预案。

## B（边界）
- 六类慎用场景（24.9）：单区域业务、严格数据驻留（须按区域配置甚至放弃边缘缓存）、高正确性风险回答不进语义缓存、边缘算力受限只做粗筛、区域能力差异无法一刀切、成本反转（流量小/命中率低时边缘额外成本超收益）——"不优化"也是正确选择，与"最低充分架构"一致；成熟度不是越高越好（L1 单区域、L2 全球化初期、L3 严格门禁、L4 大规模全球化）。
- 所有性能数字为原书示例假设（24.9 明确声明）：网络占比"超 40%"与"超 30% 为阶段三信号"等均为示例，用途不同不构成矛盾，但正式实施前必须以企业基线与压测校准，不得直接引用为阈值。
- 语义缓存的越权与串租户风险：缓存键漏掉租户/权限域/版本任一维度即埋雷——与第 5 章"隔离必须在查询边界完成、先跨作用域召回再提醒模型不泄漏即已失败"的反例同构；个性化答案误命中是缓存特有的失败面。
- 安全边界：边缘三层过滤只能覆盖直接注入；检索内容、工具返回等间接注入必须回 Region 结合完整上下文检测审计，不能因边缘有 AI 护栏就撤 Region 深层检测。
- 归因纪律：多区域/单区域对比是定位 Skill vs 路由的判据，"看到失败就改 Prompt"在此同样无效；边缘灰度验证的是站点配置变更，不能替代模型发布单元的验收（后者归 tuning-attribution 的五门禁）。
- 与相邻能力分工：模型发布灰度归 tuning-attribution；评估基线思想复用 golden-badcase 但数据源为边缘观测；ESA 接入、ESA AI 加速网关、边缘 Trace 平台职责等为阿里云产品实现，判 reference——分工判据、三条件、指标口径、阶段/成熟度决策为通用架构方法。
