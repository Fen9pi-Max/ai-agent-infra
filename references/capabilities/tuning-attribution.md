# 调优归因与模型调优路线（归因次序 + 三层验证 + 四组对照 + SFT/RL/蒸馏选择 + 五门禁灰度）

## R（原文摘引）
> 两条主线不是先后依赖，也没有高下之分，进入哪一条由归因决定：先排除能够独立复现的执行环境故障，再检查 Harness 是否提供了充分信息与可靠控制，最后才判断是否属于模型能力缺口。（调优篇导读，另见 17.1.1）
> 执行环境：绕过模型直接调用相应工具或服务；若故障仍能复现，则归因于执行环境。Harness：固定模型和执行环境，修正上下文、工具协议或运行控制；若问题明显减少，则归因于 Harness。（17.1.1 表 17.1-1）
> 对于模型与 Harness 边界不清的问题，可以在执行环境稳定的前提下组织四组对照：原模型与原 Harness、原模型与候选 Harness、候选模型与原 Harness、候选模型与候选 Harness。（17.1.1）
> 有明确示范时选择 SFT。当工具使用、任务推进或失败恢复已有较明确的有效示范，而模型执行不够稳定时，可以通过监督微调提高这些行为在相应条件下出现的概率。（17.1.4 图 17.1-3）
> 可采用"单位成功任务成本"，即统计期内全部任务的执行成本除以成功完成的任务数量，失败任务消耗的资源也计入分子。比较时应固定任务构成并同时报告成功率。（17.1.3）
> 准入不能依赖一个加权总分，而应采用"硬门槛 + 目标收益"：任何关键兼容性、安全或能力回归不合格都应阻断发布。（17.5.3）
> 只有被持续观察到、影响明确且可验证的问题，才应进入下一轮优化；单个偶发失败不应自动触发训练。（17.5.5）

## I（解释）
1. **归因先于训练，且次序有成本含义**：同一失败现象（任务未完成、工具选错）可映射到执行环境、Harness、模型三层，现象与根因是多对多。固定两层、验证一层才能判定；先查最便宜的（环境）、再查次便宜的（Harness）、最后才动最贵的（模型训练）——训练改变条件行为分布，修不了"信息没进上下文、协议含混、服务不可用"这类供给问题。
2. **四组对照拆模型×Harness 交互**：边界不清时用 2×2 对照（原/候选模型 × 原/候选 Harness），同任务集同预算，把模型改动、Harness 改动与二者交互的收益分开；候选模型配套的 Prompt/权限适配必须单独记录，否则组合收益会被记到模型头上。
3. **归因模型后才拆目标**：沿"接收观察—决策—反馈—调整"循环把缺口归入四类决策能力（任务理解/工具使用/多步决策/失败恢复与终止），再从质量、可靠性、成本三维设可验证目标，训练前锁七要素（任务、基线、门槛、可靠性、预算、安全、回归范围）。
4. **方法选择看学习信号**：正确行为可示范→SFT（样本可见性是硬约束：目标动作不得使用决策时刻之后的信息）；路径优劣只能靠执行判断且环境能给可验证反馈→Agentic RL（六维准入，先建环境与验证器）；教师已具备能力且目标是迁移/压缩/部署→蒸馏（任务—职责—风险矩阵 + 可教性测试）。三者不互斥可组合。
5. **验收与发布防两类假象**：训练损失下降≠能力（必须固定 Harness 自主运行收真实反馈，防"续写式"评测）；发布不走加权总分，走五门禁（接口兼容/目标收益/能力回归/运行预算/安全硬门禁），灰度四阶段，回滚以完整发布单元（模型+Harness+环境+评测配置）为单位。
6. **成本核算与下一轮触发**：单位成功任务成本 = 全部任务成本÷成功数（失败消耗计入分子），蒸馏决策算盈亏平衡量 N* = F/(C̄old−C̄new)；下一轮优化要"稳定复现 + 影响超阈 + 责任层确认 + 可验证修复路径"四条件齐备才立项。

## A1（原书案例 + 合成演练）
- 原书调研（2026 报告·七）：评估基建与调优质量强相关——人工抽查 55%、基于轨迹自动评估仅 6%、28% 无系统性评估体系；有评估手段的企业任务成功率达 70% 以上者约为无评估企业的两倍，已上线持续迭代企业达 84%（c-06/c-07）。归因次序在运维场景的同构体现：吉利汽车先统一数据底座再上智能运维——"没有基础治理，Agentic Ops 根本没办法识别"（实践篇，c-31，量化 MTTR 未说明）。
- 合成演练（原书未提供端到端数值案例，按 17.1.3/17.4.5 公式复算）：退款 Agent 报工具超时→绕过模型直调退款工具，超时复现→归因执行环境，修工具/资源，不触发训练。另一例"信息充分时跨任务稳定选错工具"→四分类定位②类缺口→选 SFT（可示范）→检查样本可见性→固定 Harness 自主运行验收。核算：1000 任务总成本 ¥86,000（含失败消耗 ¥16,000）、成功 800 → 单位成功任务成本 = 86000÷800 = ¥107.5（同时报告成功率 80%）；蒸馏换小模型后 ¥85/成功任务、一次性投入 F=¥500,000 → 盈亏平衡 N* = 500000÷(107.5−85) ≈ 22,223 任务。

## A2（情境应用）
场景：Agent 效果差要决定"换模型/训模型还是改系统"时；模型对比实验出了高分但不敢信时；以降本为由启动 SFT/蒸馏前算账时；训练完成准备上线时；上线后又出新问题决定下一轮投入时。
语言信号：「这问题该训模型还是改 Prompt」「先查环境还是先查模型」「SFT / RL / 蒸馏怎么选」「微调能降成本吗」「模型上线怎么验收、怎么灰度」「attribution / fine-tune / distill / reward hacking / rollout」。
区分（初稿）：trajectory-pipeline 提供归因所需的轨迹证据，本卡消费证据做"改哪层"的决策；golden-badcase 提供验收用的题库与实验基础设施，本卡决定训练类改动的门禁与灰度；controlled-evolution 处理改 Harness/Skill/经验资产的 Agent 主线，本卡只管模型主线（SFT/RL/蒸馏/发布），f4-28 五路径映射是两卡衔接点。

## E（执行步骤）
输入契约：失败现象描述 + 至少一条轨迹/调用记录 + 任务构成与预算信息；无轨迹记录时先回轨迹采集与可观测接入，不能凭印象归因。
1. 三层归因（固定两层验证一层）：①绕过模型直调涉事工具/服务，故障复现→执行环境，修复后结束，不触发训练；②固定模型与环境，只修正上下文/工具协议/运行控制，问题明显减少→Harness；③固定 Harness 与环境重复测试或换模型对照，错误跨任务变体稳定出现→模型。完成标准：归因结论附复现证据或对照数据，未验证的归因只算假设。
2. 边界不清时组织四组对照：执行环境稳定前提下构建 2×2（原/候选模型 × 原/候选 Harness），一致任务集与预算，拆主效应与交互效应；候选模型的 Prompt/协议适配纳入配置记录。完成标准：四格结果表 + "收益来自哪一层"的分离结论。
3. 拆能力缺口并预设验收（判停：步骤 1-2 归因到环境/Harness 则跳到步骤 7）：按四分类定位缺口；写质量/可靠性/成本三维指标与训练前七要素（任务、基线、门槛、可靠性、预算、安全、回归范围）。完成标准：缺口清单 + 指标与门槛在训练开始前成文。
4. 选方法并落实前置：可示范→SFT（监督目标拆到具体决策点；样本可见性硬约束；配比防回退）；需执行判断且结果可验证、环境满足可执行/可重置/可复现/可审计/可隔离→RL（结果可验证优先于过程可标注；高风险约束必须系统控制不只靠负奖励）；教师领先且目标为规模/成本/时延→蒸馏（先做任务—职责—风险矩阵与小规模可教性测试）。完成标准：选择理由逐条对照判据，不满足的前置项列为优先处理。
5. 验收：候选在固定 Harness、工具接口、执行预算下自主运行接收真实反馈（禁续写式评测），按质量/可靠性/成本/安全四维报告；测试集按任务族/模板/来源分组防泄漏；有采样随机性时重复运行报波动。完成标准：四维评测报告 + 交付物（候选模型/适配器、训练与推理配置、数据版本）。
6. 发布：冻结模型/Harness/环境/评测四类配置为候选发布单元，跑纯模型对照与部署组合对照两组；看结果前预设五门禁阈值与非劣效界值；灰度四阶段（影子→低风险→扩量→稳定替换），每阶段预设扩大/暂停/回滚条件；回滚以完整发布单元为单位。完成标准：门禁逐项记录 + 灰度与回滚预案。
7. 下一轮触发：新版本轨迹、Badcase、成本变化与回滚事件绑定发布单元，重新三层归因；满足稳定复现 + 影响超阈 + 责任层确认 + 可验证修复路径才立项。
输出契约：归因结论与证据、四组对照表、方法选择记录、四维评测报告、五门禁与灰度决策、下一轮触发判断。

## B（边界）
- 现象不能直接决定归因（17.1.1）：工具选错可能是能力不足也可能是描述含混——无验证实验支撑的归因结论、跳层直接训模型/换模型，是全书代价最高的误判（模型训练修不了供给问题，只在缺陷条件下过拟合表象）。
- 组合变更归因混淆：候选模型配套大幅 Prompt 扩写/额外重试/放宽权限取得的高分，不能记在模型头上；一轮实验同时换模型、改 Prompt、加 Skill 则分数变化无法解释（17.5.1/22.4 反例）。
- 训练≠降本：低频或变化快的任务用轻量 Harness 调整更经济；不核算一次性投入（数据/训练/评测/发布/维护）与盈亏平衡任务量就启动 SFT/蒸馏，总成本可能不降反升；只比 token 单价会忽略学生额外步骤与重试。
- SFT 数据红线：不确定结果不当监督标签；成功轨迹不全盘模仿（错误动作保留上下文但屏蔽损失）；训练与推理模板兼容、截断不丢依赖；训练后普遍增加工具调用说明配比失衡。
- RL 红线：验证器只查表面结果会训出"更快创建不合规退款"；训练奖励上升≠能力提升，发布结论必须来自隔离的独立评测；截断不当失败、旧失败轨迹不无限回放。
- 蒸馏红线：教师不稳定则蒸馏只是高效复制错误；只用最终答案学不到工具时机与异常恢复；离线蒸馏忽视学生状态偏移。
- 发布红线：加权总分让安全缺陷被高分平均掉；门槛须在看结果前定；回滚只切模型权重会形成不兼容组合；回滚不能撤销已完成写操作（需幂等/审计/补偿）。
- 与相邻能力分工：轨迹检索与 Pipeline 归 trajectory-pipeline；黄金集/评估器/实验归 golden-badcase；改 Skill/Harness/经验资产归 controlled-evolution；单个偶发失败不触发训练（触发纪律见 golden-badcase 的 Badcase 闭环）。
