# 行动契约（行动链七步 + 看见/注册/授权三分 + ALLOW/DENY/ASK + PACV + HITL）

## R（原文摘引）
> 一个完整的行动链不应从"调用 Tool"开始，也不应在"返回文本"处结束。（第 6 章 6.1.1）
> 若"出现在 Tool Schema 中"就等价于"可以调用"，最小权限、用户委派和阶段性只读模式都无法成立。（第 6 章 6.1.1）
> 仅按 Tool 名称做静态白名单，无法区分"读取一条测试记录"和"导出整个生产库"。（第 6 章 6.4.1）
> 不可逆或高影响动作可以统一采用"Preview—Approve—Commit—Verify"模式。（第 6 章 6.4.2）
> Agent 获得的工具、网络、数据和凭证越多，潜在的影响半径（Blast Radius）越大。（第 2 章 2.1.3）
> Prompt Injection 的关键防线是区分指令与数据。（第 6 章 6.4.4）

## I（解释）
1. **行动链七步**：Model Intent→Schema 校验→身份绑定→策略判定（ALLOW/DENY/ASK）→审批/HITL→隔离执行→Observation+State/Trace 回流。三个防混淆前提：能力被发现≠已授权；参数符合 Schema≠意图符合目标；Sandbox 成功≠结果可影响生产。任何环节缺失，模型建议就直接变成系统事实。
2. **看见/注册/授权三分 + 统一契约**：模型看见工具（描述进 Context）≠Harness 注册（知道怎么调）≠当前用户/任务获授权（这次行动可以发生）。所有连接方式统一为 Action Request/Result 契约（action_id/能力版本/参数 Schema/actor/资源范围/副作用与可逆性/幂等键/审批要求；结果含结构化状态/错误类别/可重试性/副作用标记/State Patch 候选）——预算、权限、审计、重试不必按连接方式重复实现。
3. **要素化权限决策**：决策看主体/租户/目的/能力/参数/目标资源/环境/阶段/敏感度/影响范围/可逆性/历史审批，不只看工具名。ASK 不是默认兜底：优先用更窄 Tool、参数约束、预览、资源范围、Sandbox 降风险，只在目的或后果无法由策略判断时才请人。
4. **HITL 三层 + PACV**：Plan 审批/Action 审批/结果验收三层次；审批请求要素（做什么/为什么/以谁身份/作用于什么/预计影响/是否可逆/批准范围）。不可逆高影响动作走 Preview→Approve（绑定身份与对象版本）→Commit（幂等键）→Verify（查真实系统交付证据），验证失败进 Repair/Compensate/Escalate。
5. **协议、环境与事件**：Function Calling（意图接口）/MCP（能力连接）/A2A（独立任务循环的远程 Agent）按"是否拥有独立循环+异步状态+Artifact"选择，协议不替你做授权/隔离/语义验证；窄 Tool 优先于通用 Shell/Computer Use，环境以 Environment Contract 声明；Secret 不进模型可见位置、执行侧短时凭证；网页/工具结果/远程 Agent 返回均为不可信数据，读取与执行阶段隔离；外部事件八类（Text/Progress/Tool/State/Approval/Artifact/Error/Usage）让审批与进度对用户可见可操作。

## A1（原书案例 + 合成演练）
- 原书·实践案例（第 29 章 GOAI 作品）：RevGuard 渠道佣金核算——金额不由模型产生，规则引擎精算+审批令牌，模型只组织流程/匹配政策版本/解释差异（c-18）；CyberGuard 安全处置——每次授权绑定具体提案与目标对象，执行角色不能自行扩大范围，独立复测有权推翻上一轮结论（c-20）；OpsKeeper 生产操作——故障工单、处置提案、目标对象与具体指令四标识全匹配才执行，任一不符即拒绝（c-21）；店巡 Agent——执行者不自证处置成功，独立 Auditor 重查设备状态/批次/工单/审批，双路径通过才关事件（c-16）。
- 合成演练（纸面推演，非原书案例）：客服 Agent 两类动作——权限决策表：改地址=工作区级可逆+用户确认→ASK 或 ALLOW+Diff；退款>500 元=DENY 转人工；退款≤500=ASK；长期凭证/绕过审批=DENY。决策要素含参数与资源范围而非仅工具名；退款走 PACV（幂等键防重复扣款，Verify 查退款流水并交付证据）；"创建退款单"与"执行退款"拆为两个 Action（风险/可逆性/审批不同）；订单备注/客户消息标记为不可信数据，读取与执行隔离；审批后 Harness 重校验对象版本。核验：每个动作有判定+依据+审计记录，注入场景不改变授权范围。

## A2（情境应用）
场景：给 Agent 接工具/接生产系统、设计权限模型时；高危操作（发布/支付/删数据/发消息）要加审批时；用户要在运行中干预（Steering/中断）时；工具返回内容可能被注入时。
语言信号：「Agent 能不能直接动生产库」「权限怎么设计、白名单怎么画」「高危操作怎么加人工确认」「怎么防 prompt injection 借工具搞事」「tool permission / approval / HITL / blast radius / action plane」。
区分：环境形态选型/隔离后端/Sandbox 生命周期归第 7 章环境单元（本卡只保留行动侧的风险控制与 Environment Contract）；网关三层治理语义（LLM/MCP/Agent Gateway）归第 9 章；企业级攻击面防护/红队归第 14 章安全单元（本卡只管单 Agent 行动侧的 Guardrail 部署位）；多 Agent 通信面选型归 A2A 相关单元；Plan Mode 的任务语义归 task-contract，本卡管其权限模式执行侧。

## E（执行步骤）
输入契约：动作清单（每动作的业务目的/参数/目标资源）、风险分级（只读/可逆/不可逆/高影响）、身份与租户模型、审批可用的人力与通道、目标环境约束（网络/凭证/出站）。
1. 盘点动作并拆粒度：列出全部动作，按"一个可描述、可授权、可观察、可验证的业务动作"拆分（创建变更单与生产发布分开；能用窄 Tool 的不用通用 Shell）。完成标准：每动作有风险/可逆性/审批要求标注；无粗粒度混合工具。
2. 落七步链与统一契约：为每动作定义 Schema 校验→身份绑定→策略判定→审批→隔离执行→Observation→State/Trace 的落点；Action Result 含结构化状态与副作用标记。完成标准：自由文本不承载身份/参数/影响范围（由确定性代码校验）；无"返回文本即结束"。
3. 建权限决策表：按决策要素（主体/资源/参数/范围/可逆性/阶段）产出 ALLOW/DENY/ASK 映射，含幂等键与拒绝原因结构（缺角色/委托过期/越界/待审批）。完成标准：读一条 vs 导整库可区分；拒绝可解释可恢复。
4. 高影响动作上 PACV + HITL 层：Preview 展示接近实际提交的影响（不可回滚明示）→Approve 绑定身份与对象版本→Commit 幂等执行→Verify 交付环境证据，失败进补偿/升级；审批回调后端按当前身份/租户/资源版本再做确定性判断。完成标准：每个不可逆动作有四步落点与补偿路径；审批后重校验在场。
5. 定环境与事件模型：Environment Contract（文件范围/网络出站/Secret 引用/配额）声明并前置失败；不可信内容标记与指令/数据区分落位；对外事件（State/Approval/Artifact 至少三类）按接收者身份生成视图，断线按事件 ID 续接去重。完成标准：注入场景演练不改变授权范围；出站默认限制。
输出契约：动作清单+风险分级表 + 权限决策表 + PACV 流程定义 + 事件与审计记录格式。判停：无身份模型或无审批通道时，高风险动作一律 DENY 并明确缺口——不允许"先跑了再说"。

## B（边界）
- 策略只靠提示词实现即失效（ce-02）：权限/审批/审计写在 Prompt 里，模型概率性行为可绕过——策略必须在模型调用、工具调用、状态变更等确定性环节强制执行。
- 三分混同（ce-07/ce-28）：跳过权限判定/参数校验/隔离执行任一环节，"模型看见工具"="有权执行"，最小权限整体失效。
- 自由文本承载身份与参数（ce-29）：行动请求的能力名/参数/影响范围取自模型自然语言输出，注入与幻觉直接进执行链。
- 粗粒度工具隐式扩权（ce-31）与通用通道拼生产操作（ce-32）：对"创建"的 ALLOW 连带授予"发布"；通用 HTTP/Shell 使参数、目标与身份全部失去校验点，SSRF 与误操作直达生产。
- 越权后往 Prompt 加"谨慎发布"（ce-40/ce-41）：正确 Patch 是拆分能力+策略校验审批类型/对象版本/目标环境/短时授权；Policy 仅按工具名匹配返回 ALLOW 是语义滑移。长期凭证（ce-45）、入口一次检查（ce-46：有效权限是动态交集，每次实际访问前重新决策）、拒绝只回"无权限"（ce-53：拒绝原因是恢复路径输入）均为高频事故点。
- Sandbox 只约束技术可达范围，不回答授权与正确性（2.3.3）：不能因有沙箱省略工具权限判定、业务审批与结果校验；隔离粒度按风险选（进程/容器/微虚拟机）。
- 适用边界：具名协议与 API（AG-UI/A2UI、canUseTool 回调）具时效性，以机制对应吸收；企业级攻击面/红队/深度防护归第 14 章安全单元，本卡止于单 Agent 行动契约；原书风险映射示例（读文件 ALLOW、发布支付 ASK/DENY）是起点不是终点，须按业务重标定。
