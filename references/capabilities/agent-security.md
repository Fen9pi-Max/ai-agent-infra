# Agent 安全防护（盾与缰绳 + 五攻击面 + 双向授权 + 出站默认拒绝）

## R（原文摘引）
> Agent 安全既要解决"不被打穿"，更要解决"不越边界"。……盾保证它不被利用，缰绳保证它不被放纵。（第 14 章 14.1）
> 攻击者能够施加影响的位置，也随之从用户输入和业务接口，扩展到工具描述、任务状态、跨 Agent 消息及中间执行结果等。（第 14 章 14.2.2）
> 只为 Agent 配置一个应用账号或长期密钥，无法回答"谁在行动、代表谁行动、凭什么行动、为什么此刻允许、发生异常后如何收权"。（第 14 章 14.5.1）
> 新令牌仅包含被授权的最小 scope；保留用户信息，又记录 Agent 调用链。这避免了 Agent 成为"超级应用"。（第 14 章 14.5.3）
> 默认拒绝的出站策略：Agent 运行时所在的 VPC 或子网默认禁止出站，仅按域名、目的地显式放行业务必需的端点。（第 14 章 14.6.4）

## I（解释）
1. **双主线认知**：Agent 既是被攻击对象（供应链投毒、提示注入、系统入侵）也是行为主体（持权限、自主调工具、接触敏感数据，未被攻击也可能越界）。防护是盾——全栈纵深设防；管控是缰绳——身份鉴权、逐次调用校验、高危操作二次授权、数据出域阻断。只设盾不配缰绳时，自主性越大损失越大。
2. **五类攻击面做威胁建模起点**：①不可信外部输入（网页/邮件/文档/检索记录，能影响 Agent 读到的内容就能间接影响执行）；②工具发现与调用（工具描述误导 + 实际行为偏离声明的两层欺骗）；③动态业务调用与网络访问（Agent 生成 URL/SQL 触发 SSRF/注入）；④结果交付边界（输出被渲染/发布时触发危险解释）；⑤重试并发机制的拒绝钱包攻击 DoW（每次调用合规、累计成本失控）。
3. **应用层双向设防**：入向防操纵（外部内容与任务指令分开处理、工具接入与更新时评估、限制批量触发）；出向限影响（明确可访问目标/操作/数据范围，请求发出或业务提交前校验实际连接地址与重定向、输出外发前敏感检查，高影响操作设确认且确认内容与执行一致）。
4. **数据沿六阶段设控**：采集（分类分级/脱敏/去毒）→传输（私网+推理+协议加密）→存储（租户隔离+分层加密）→访问（访问控制与服务关联角色）→处理（护栏实时过滤）→删除（注销删除/匿名化）。
5. **身份是闭环不是账号**：八环节（发现→注册→凭据→授权→控制→审计→治理→恢复）；每个 Agent 唯一数字工牌，凭据进 Token Vault、运行时发短期令牌；双向授权——入站控制谁能调用，出站用 Token Exchange 把权限收敛到下游最小 scope，On-Behalf-Of 默认不超过用户权限且首次同意可撤销。
6. **计算与网络兜底**：会话级沙箱/microVM 内核级隔离、用完即弃、按会话注入临时凭据；出站默认拒绝仅放行业务必需端点，网络层封禁云元数据端点与内网保留段（防 SSRF 升级为凭据窃取），Agent 出站经统一关口收敛并留日志。

## A1（原书案例 + 合成演练）
- 原书案例（第 29 章与实践篇转述）：①GOAI 决赛作品 CyberGuard（安全处置）：七类职能角色 + 四次人工审批，高风险动作与人工授权严格绑定——每次授权对应一个具体处置提案与明确目标对象，执行角色不能自行扩大范围；独立复测有权推翻上一轮结论，一次运行完整演示异常恢复、目标修正、动作回滚与两轮复测。②Agentic SOC（AI 安全产品研发）：SOCBench 版本化基线 211 个真实调查任务覆盖 16 类场景/9 维度/5 阶段，攻击者-受害者识别反转缺陷修复后固化为共享字段+回归样本两类资产持续复测（具体提效百分比未说明）。③Hugging Face 入侵事件（书中转述）：攻击 Agent 借可访问的中间服务（Artifactory）代联网突破网络边界——出站默认开放的真实代价。
- 合成演练（按原书规则推演）：为"查内部订单库（只读需求）+ 调用一家外部物流 SaaS"的客服 Agent 出防护清单。五攻击面枚举并逐面映射控制；出站请求校验实际连接地址与重定向、输出外发前敏感检查；授权链设计为入站 scope + 出站 Token Exchange 收敛到"订单库只读 + 物流 SaaS 最小 scope"，OBO 首次同意可撤销；出站默认拒绝，仅放行模型 API 与物流 SaaS 域名，封禁云元数据端点与内网段；会话级沙箱按会话注入临时凭据；身份五问自检收尾。可核验输出：五类攻击面每类至少一条已映射控制；授权链满足 Agent 权限 ≤ 用户权限；白名单不含元数据地址/内网保留段；高危操作确认内容与执行一致。

## A2（情境应用）
场景：给接入内部系统与外部 SaaS 的 Agent 做安全方案评审；Agent 要获得生产库/资金操作权限前的授权设计；发生越权、泄露或可疑外联事件后补防线；合规审计要求提供 Agent 权限治理证据；担心提示注入/工具投毒改变 Agent 行为。
语言信号：「Agent 要访问生产库，权限怎么给才安全」「提示注入怎么防」「Agent 会不会被攻击者当跳板」「出站流量要不要管」「API Key 放哪、离职了怎么收权」「DoW/钱包攻击是什么」；英文 trigger：prompt injection / SSRF / least privilege / egress control / token exchange / threat model。
区分（初稿）：observability 管事后还原与审计（证据链），本卡管事前/事中拦截（Guardrail）与权限收敛——出事后查证据用 U15，防出事用本卡；asset-governance 管 Skill/MCP 等资产的生命周期与版本机制，本卡只承载其中"接入与更新时的安全评估规则"（工具描述与行为偏离、外部内容隔离）；防线建好后要验证 Agent 在攻击下 behave——上线前验证归 agent-simulation。

## E（执行步骤）
输入契约：Agent 清单与用途、数据访问需求（读/写、对象、范围）、外部依赖（模型 API/SaaS/MCP/网络）、用户群与现有身份体系、高危操作定义。缺"高危操作定义"必须先与业务方确认"允许做什么、需要审批什么、绝不能做什么"，不能静默跳过确认环节设计。
1. 威胁建模：按五类攻击面逐一枚举本系统的具体入口，每类至少映射一条控制措施。完成标准：攻击面→控制→实现层三点映射表无空格。
2. 应用双向防护：入向——外部内容保留来源与任务指令分开处理，工具/MCP/技能配置纳入管理并在接入和更新时评估，限制批量触发与资源消耗；出向——明确可访问目标/操作/数据范围，请求发出或业务提交前校验（数据库参数化查询、网络请求校验实际连接地址与重定向、输出渲染发送前安全处理与敏感检查），高影响操作设确认环节且确认内容与实际执行一致。
3. 数据六阶段：采集（盘点来源→分类分级→脱敏→去毒）→传输（私网/推理/协议加密）→存储（隔离+分层加密）→访问（访问控制+服务关联角色）→处理（护栏实时过滤）→删除（按隐私政策删除/匿名化）。完成标准：六阶段各有至少一条已落地控制。
4. 身份与授权闭环：盘点注册（唯一 Agent ID、数字工牌）→ Token Vault 托管凭据、运行时短期令牌 → 双向授权（入站 scope；出站 Token Exchange 收敛最小 scope）→ OBO 首次同意可撤销 → 生命周期与人员异动同步。完成标准：身份五问（谁在行动/代表谁/凭什么/为何此刻/如何收权）逐条可答。
5. 计算层与会话隔离：每会话独立沙箱或 microVM、内核级隔离、用完即弃、空闲超时自动回收，按会话注入最小临时凭据；多 Agent 按任务边界划分运行环境与网络策略。
6. 网络出站管控：默认拒绝、按域名显式放行业务必需端点；网络层封禁云元数据端点与内网保留地址段；Agent 对互联网及 MCP 服务的访问经 AI 网关或防火墙统一关口收敛，校验目标、记录日志、与检测联动。
输出契约：威胁建模表 + 防护清单（攻击面→控制→实现层）+ 授权链图（入站/出站 scope）+ 出站白名单 + 身份五问自检结论。判停：无法定义高危操作清单时，确认环节设计不能开工；纯离线、无外部依赖、无敏感数据的 Agent 可裁剪步骤 3/6 并记录裁剪理由。

## B（边界）
- 只防"不被打穿"不管"不越边界"是结构反例（第 14 章，ce-54）：IBM 调研中发生 AI 安全事件的机构 92% 缺乏适当的 AI 访问控制——盾与缰绳缺一不可，且每个技术层都同时承载两者。
- 出站默认允许 + 未封元数据端点是高频真实漏洞（ce-70/71）：HF 入侵事件即借中间服务代联网突破边界；Agent 生成 URL 的能力使其成为 SSRF 理想载体，网络层不封禁时应用层校验形同虚设。
- 凭据与身份反例：把用户长期凭证（密码/AK/SK）交给 Agent，一次泄露长期有效且审计无法还原责任链（ce-45/66）；调用者能访问 Agent 就默认 Agent 能访问调用者全部资源是权限放大通道，出站边界不得超过入站请求形成的授权边界（ce-47）；权限只在入口检查一次，长任务中环境与数据等级变化后不再复查，越权发生在入口检查之后（ce-46）；离职员工 Agent 继续运行是权限残留（ce-65）。
- 修复位置反例：越权后往 Prompt 里加一句"谨慎发布"无效（ce-40）——越权根因在权限模型/策略实现层，Prompt 警告是概率性软约束且无回归用例锁定；权限策略只按工具名匹配会把"同意草稿"滑移成"允许生产发布"（ce-41）。
- 防线依赖反例：仅靠"提示词加密 + 模型拒答"防蒸馏有先天缺陷（第 14 章 14.4.3）——拒答能力不稳定，且可用大模型返回的加密令牌询问同系列弱安全小模型绕过。
- 适用边界：与 U15 的分界是"事前/事中拦截 vs 事后审计"——上下文不足或开放式语义判断的结论应进异步调查（U15 的研判链路），不做实时阻断；护栏九维度是能力清单，具体产品选型与 S1-S4 模板、PrivateLink 等实现细节按部署环境裁剪，框架本身通用；身份协议（OIDC/Token Exchange）是通用标准机制，非厂商专有。
